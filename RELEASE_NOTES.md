## Changes

- Expand the OpenAI/OpenRouter assistant to operate the app beyond settings: monitor views/filters and local inspection, detailed profiles and change evidence, reviewed change management and saved explanations, packet capture/stop/import, JSON export, executable reveal/selection, rule enable/remove/bulk disable, geographic and exclusive policies, and guarded update actions. Local file pickers and exact single-use reviews control execution; broad policies show scope acknowledgement and country-only exceptions.
- Keep chat available during approved background tasks, with fresh progress and cancellable Windows rollback. Exclude live status, packet metadata and view actions from investigation caching. Packet contents remain local, and app settings/credentials remain outside tooling.

- Add only two investigation controls: **Raise the tool limit by 6** and **Summarize & continue**, available during active responses and on the latest limit summary. Budget increases are bounded and visible; checkpoints summarize and resume once. No separate Continue investigation button is included.
- Reuse successful timestamped lookups across resumed passes, including IP/web research, and carry forward the original request, citations and unfinished calls. Repeated proposals reuse their existing review card without changing rules or extending approval expiry. In-memory investigations expire after ten minutes and are invalidated by cancellation, fresh questions, privacy changes and credential changes.
- Replace AI-console round/tool-limit errors with a final tool-free summary of collected results. Keep the six-round/eight-tool budgets, stop extra calls mid-batch, preserve citations and local approval cards, and show a clearly labeled local recap if the model cannot summarize. Support both OpenAI and OpenRouter; cancellation/privacy checks remain active during summarization.
- Add **What is this?** to the right-click menu of every data-table row, including nested connections, saved profiles/services, changes, packet headers and firewall rules. Return a short read-only explanation through the configured AI provider; support Shift+F10, setup, cancellation, errors and dark/light layouts. Only validated metadata is sent, excluding addresses, full executable paths and packet contents; no action or web tools are exposed.
- Enable direct OpenAI chat in the AI console using the saved OpenAI provider, model and encrypted token. Add stateless Responses API function calling, in-memory reasoning/call replay and opt-in isolated OpenAI web research with validated citations. Existing traffic/history tools and locally approved block/unblock actions work with either provider.
- Replace the AI model text field with a dropdown of OpenAI models for both OpenAI and OpenRouter. Preserve the saved selection and provide a custom model ID option for other models and compatible endpoints. No catalog request or token sharing is needed to choose a model.
- Add an OpenAI/OpenRouter chatbot in a starship command panel with live tool activity, background responses, cancellation, and session reset. Show the active provider in the console and privacy notices.
- Let the assistant inspect current applications/connections, saved traffic profiles, grouped changes, and Watchmen rules through bounded local tools.
- Add opt-in public-IP lookups and cited web research. The app uses fixed HTTPS endpoints, disables the default web plugin, and keeps public-IP sharing off by default. Lookup preferences persist locally; chat and tool results remain in memory.
- Let the assistant prepare persistent app/connection/destination blocks and single-rule unblocks. Exact executable and endpoint scopes are reviewed locally; only a user approval can execute a proposal. Stale/expired reviews, invented targets, unsupported tools, and replayed approvals are refused. Existing administrator and verification requirements still apply.

## Known limits

Use an OpenAI or OpenRouter model with function/tool support. Custom compatible endpoints remain limited to one-shot insights. Web research depends on model/account support and may add search charges; IP lookups may be rate-limited. Incomplete responses show a retry/narrower-question message. Integration tests simulate both providers and native rule transport; no paid inference or global firewall policy was used in validation. Large geographic filter sets can still hit Windows resource limits (`0x000005AA`). Windows installer binaries remain unsigned; updater downloads are verified against the release feed.
